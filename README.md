# figure_flow

Short narrated videos in a simple hand-drawn style, authored entirely as code
and data. A stick figure walks in, turns, and sits cross-legged; the narration
drives the timing. No GUI animation tool, no timeline to click around in, no GPU.

Comes with a browser-based pose editor for dragging the figure into shape.

## Quick start

Requires [asdf](https://asdf-vm.com) (Node 24.15.0 is pinned in `.tool-versions`),
`pnpm`, and Homebrew for two native dependencies:

```bash
brew install ffmpeg cmake
pnpm install

pnpm dev      # Remotion Studio — preview and tune scenes
pnpm editor   # Pose editor — drag joints, edit keyframes
```

Then render:

```bash
pnpm exec remotion render MeditationFigure out/meditation.mp4
```

## How it works

```
narration.txt ──▶ draft.wav ──▶ captions.json ──▶ scene renders ──▶ shot.mp4
    (tts)         (transcribe)                     (Remotion)
```

**Timing comes from the narration, not from counting frames.** A script is spoken
by macOS `say`, transcribed locally by whisper.cpp for word-level timings, and
scenes ask questions like *"which frame is the word 'settles' spoken on?"*
Re-record the voiceover and the animation re-times itself.

**Lines are drawn, not stroked.** [roughjs](https://roughjs.com) redraws every
shape as sketchy pencil work. Seeds are derived from the frame number, so the
linework *boils* like hand-drawn animation while staying bit-for-bit
reproducible between renders.

**The figure is a 2D bone rig.** A pose is a set of joint angles; positions are
always derived from them and never interpolated directly, so limbs cannot
stretch. A walk is four hand-authored poses — contact, down, passing, up — with
the second step generated by mirroring the first.

## The pose editor

```bash
pnpm editor   # http://localhost:5183
```

- Drag any of the 14 joint handles. **Aim** rotates the bone you grabbed;
  **IK** bends a two-bone chain so a hand or foot reaches your cursor.
- Scrub, play, and key an animation on the timeline. Set easing per segment,
  mirror a cycle's second half, undo.
- Create new poses and tracks, saved straight to `poses/` as JSON.

The editor imports the same modules the video renderer uses — there is no
second implementation of the figure to keep in sync.

## Layout

| Path | |
|---|---|
| `src/lib/figure/` | Skeleton, pose maths, interpolation, IK. Pure TypeScript. |
| `src/lib/rough/`  | roughjs helpers and boil seeding. |
| `src/lib/poses/`  | Pose/track file format, validation, editing operations. |
| `src/scenes/`     | The videos. Each is a React component registered in `Root.tsx`. |
| `poses/`          | Pose and animation data as JSON. Shared by scenes and editor. |
| `editor/`         | The pose editor (Vite + React). |
| `scripts/`        | Narration synthesis and transcription. |

Compositions: `MeditationFigure` (the finished shot), plus `WalkCycle`,
`FigureCheck`, `RoughLab`, `OutlineLab` and `SmokeTest` for development.

## Testing

The pose maths, IK, angle handling and track editing are pure TypeScript with
no React or Remotion imports, so they are tested without a browser. The tests
that matter most assert properties rather than values: limb lengths survive
interpolation, an IK solve actually places the tip on its target, and a walk
cycle's mirrored half still matches its authored half.

Rendering has its own check — render the same frame twice and compare hashes.
Identical means the boil seeds are under control; two frames in different boil
steps must then *differ*, proving the linework is animating. Both must hold.

`tsc` does not gate rendering: Remotion's bundler strips types without checking
them, so a green render proves nothing about types. Run the typecheck.

## Contributing

This is a personal project for learning animation by building it, so it is
opinionated and moves in whatever direction is interesting. Issues and pull
requests are welcome; please open an issue before anything large, so you don't
spend an afternoon on something that doesn't fit.

Before submitting:

```bash
pnpm lint    # eslint + tsc
pnpm test    # 79 unit tests
```

Four things specific to this codebase, all of which are easy to break without
noticing:

- **Keep the pure modules pure.** Nothing under `src/lib/figure/`,
  `src/lib/anim/` or `src/lib/poses/` may import React, Remotion or roughjs.
  That constraint is what lets the maths be tested without a browser and the
  pose editor reuse the renderer's code. Check with
  `grep -rl '"remotion"' src/lib` — it should print nothing.
- **Run the determinism check if you touch rendering.** Render the same still
  twice and compare hashes; identical means the roughjs seeds are controlled.
  Then confirm two frames in different boil steps *differ*. Both must hold, and
  neither is covered by the unit tests.
- **Pose data belongs in `poses/` as JSON**, not in TypeScript. It is edited by
  a tool as well as by hand.
- **Read the gotchas in `CLAUDE.md`** before debugging anything odd. Most of
  them cost someone an hour to find and are silently wrong if guessed.

Tests are expected for logic; prefer asserting a property (a limb keeps its
length, an IK solve reaches its target) over asserting a specific number.
